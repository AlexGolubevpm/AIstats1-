# ADR 0016. Разрезы ADOK — настройка, бюджет планируется, а не хардкодится; разрез по форматам и поля, которые выбрасывали

Дата: 2026-10-09. Статус: принято.

## Контекст

Ночной джоб тянул по каждому сайту четыре фиксированных разреза (страны, сетки, устройства, источники); «4 на сайт» было вшито в пять мест (бэкфилл, экшен, страница интеграций, `.env.example`, документация), окно пересчёта и резерв бэкфилла задавались переменными окружения. Из бюджета 800 запросов в сутки уходило ≈ 270. Владелец просит использовать 700–750 и видеть по форматам отдельно загрузки, запросы и показы — суммы по зонам этого не дают. Поля `requests`, `broker_clicks`, `fill_rate`, `predicted_income` из ответов ADOK выбрасывались.

## Решение

1. **План вместо констант.** `AppSetting asg_cuts` (`src/server/ingest/adspyglass/plan.ts`): включённые разрезы по сайту, число прошлых дней в ночь, режим почасовых итогов. `planCost()` — единственный источник арифметики запросов; от него считаются бэкфилл (`requestsPerDay`, резерв = план + 30), подтверждение ручного запуска, тексты и живой расчёт в блоке «Разрезы ADOK» на `/settings/integrations`. Переменные `ASG_RESTATE_DAYS` и `ASG_BACKFILL_RESERVE` больше не читаются.
2. **Дефолт.** Восемь разрезов (страны, сетки, устройства, источники, форматы, зоны по сайту, часы, платформы), браузеры выключены, 3 дня, почасовые — только сегодня (вчера и так перечитывает ночь): 3 × (1 + 8 × 27) + 24 = 675 из 800 на 27 сайтах — в коридоре 700–750, который просил владелец, с запасом на повторы. Новый разрез — строка в `CUTS` плюс маппер и писатель.
   - **Зоны по сайту** (`spot` + `platforms_ids[]`): зона принадлежит отфильтрованному сайту, домен в названии — только проверка; ответ с чужими доменами (фильтр проигнорирован) переводит день на общий запрос.
   - **Часы** (`hour`) → `FactRevenueHour`: профиль дня по UTC, вкладка «Часы» на сайте (среднее за дни периода).
   - **Платформы / браузеры** (`platform`, `browser`) → `FactRevenueTech` (kind + name как прислал ADOK), вкладка «Платформы».
3. **Разрез `ad_type` → `FactRevenueFormat`.** Загрузки, запросы, показы, клики, fill ADOK и выручка формата как таковые. `v_format_daily` предпочитает разрез, а для дней без него — суммы зон; просмотры всегда из зон. Так «Форматы» на сайте и в бандле показывают реальные загрузки формата.
4. **Поля сохраняются.** `requests`, `brokerClicks`, `fillRateAsg`, `predictedIncome` — nullable во всех фактах ADOK; `FactTrafficSource.impsNetwork`. CTR (`clicks / imps_own`) — в зонах, форматах, сетках, девайсах.

## Альтернативы

- Поднять константу «4» до «5» — ещё одна правка в пяти местах, и владелец не управляет бюджетом.
- Переменные окружения для каждого разреза — требуют деплоя и правки `.env` на каждое изменение; план в базе меняется из интерфейса и виден вместе со своей ценой.
- Считать формат суммой зон (как раньше) — загрузки зоны ≠ загрузки формата, а `requests` у зон ADOK не отдаёт.

## Последствия

- Бюджет виден и управляем; при переполнении блок предупреждает, бэкфилл сам сжимается до остатка.
- Поля с `null` до даты миграции: отчёты показывают «—», а не ноль.
- Тесты: unit (`planCost`, `normalizePlan`, `mapFormatRows`, новые поля `measures`), int (разрез `ad_type` пишется, выключенный разрез не запрашивается, окна по плану, бэкфилл по резерву плана, `v_format_daily` с запасным путём), E2E (блок планировщика).

## Дополнение (2026-10-09): бюджет настраивается из интерфейса

Суточный бюджет 800 был нашим консервативным значением, а не лимитом ADOK: ADOK блокирует частые запросы, суточного потолка у него нет. В день с семью деплоями ночной прогон по плану, почасовые итоги и догрузка месяца при рестартах воркера выбрали весь бюджет, и ручной прогон за прошлый день упёрся в него. Решение: бюджет задаётся в блоке «Лимиты AdSpyglass» (`AppSetting asg_budget`, поверх `ASG_DAILY_BUDGET`), 0 — без лимита (счётчик ведётся, но не останавливает; расчёт плана получает `UNLIMITED`, бэкфилл идёт всем окном). Пауза между запросами и пауза очереди при 429 не меняются — они и защищают от блокировки.
