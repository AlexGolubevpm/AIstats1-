# 0013. Гипотезы вместо рекомендаций: хранимые, с источником, статусом и измерением результата

- Статус: принято
- Дата: 2026-10-08

## Контекст

Страница «Рекомендации» собиралась на лету при каждом запросе из открытых алертов и шести правил по отчётным таблицам. Ничего не хранилось: нельзя было принять или отклонить пункт, добавить свой, увидеть, что уже пробовали и что вышло. Правил по бандлам, сайту относительно бандла, гео относительно сети и формату относительно соседей не было вовсе — а именно так владелец ищет, где сеть недозарабатывает. Владелец попросил переименовать раздел в «Гипотезы», дать создавать их самому (бандл, сайт, формат, текст), брать из алертов и иметь блок автогипотез, который собирается ежедневной аналитикой.

## Решение

1. **Таблица `Hypothesis`.** Источник (`AUTO` — правила, `ALERT` — алерт, `MANUAL` — своя), статус (`PROPOSED` → `ACCEPTED` → `DONE`; `REJECTED`; `EXPIRED` для авто, которые перестали воспроизводиться), уровень, объект (бандл / сайт / формат / зона / сетка / гео / источник / дил), текст «если …, то …», `evidence` (цифры, на которых основана), ожидаемый эффект $/мес, метрика проверки, `baseline` и `result`. Уникальность `(ruleKey, objectKey)`: алерт и правило про один объект — одна гипотеза, алерт приоритетнее.
2. **Генерация** — `generateHypotheses` в ночном `derive` после алертов и при старте воркера. Новые → `PROPOSED`; известные — обновляются цифры и эффект, статус не трогается (у принятых и проверенных и текст не трогается); исчезнувшие `PROPOSED` → `EXPIRED`, вернувшиеся — снова `PROPOSED`; отклонённые молчат 30 дней.
3. **Правила** (`src/server/domain/hypotheses.ts`) — чистые функции над строками: шесть прежних плюс восемь новых разрезов (сайт против медианы бандла, гео против медианы сети, формат, который зарабатывает у соседей и отсутствует здесь, сетка-лидер без объёма, источник дороже выручки, недельное падение маржи с виновным разрезом, доля расхода бандла против сети, дил дешевле ротации). Каждое выдаёт ожидаемый эффект в месяц — по нему сортировка и уровень.
4. **Измерение.** «Принять» фиксирует метрику за 14 дней до; «Завершить» считает её за последние 14 дней (не раньше принятия, минимум 7 дней данных). Метрика берётся по объекту гипотезы из тех же вьюх, что и страницы.
5. **UI** — `/hypotheses` с вкладками «Предложено системой / В работе / Проверено / Все», чипами разрезов и бандлов, панелью «Новая гипотеза»; кнопка «В гипотезу» на `/alerts`; блок «Гипотезы недели» на главной; `/recommendations` редиректит. MCP: `get_hypotheses` и вьюха `v_hypotheses`, только чтение.

## Альтернативы

- **Оставить список на лету и добавить только фильтры.** Не даёт статусов, своих гипотез и истории — а без измерения результата гипотеза остаётся мнением.
- **Отдельная таблица на «свои» и прежний список на лету для авто.** Два списка про одно и то же; алерт, правило и своя гипотеза про один объект разъехались бы.
- **Считать результат статистически (A/B, доверительные интервалы).** При 27 сайтах и дневной гранулярности это ложная точность (см. ADR 0008); «до/после» за 14 дней с подписью «мало данных» честнее.

## Последствия

- Миграция `20261008090000_hypotheses`; первый запуск после деплоя (догон при старте воркера) наполняет вкладку «Предложено системой» по реальным данным.
- Новое правило = функция + строка в таблице `06-metrics.md#hypotheses` + юнит-тест ([`11-documentation.md`](../engineering/11-documentation.md)).

## Дополнение 2026-10-09 — масштаб эффекта и доказательства

Эффект гипотезы из алерта раньше брался как «деньги под риском» без учёта окна правила: $12 за неделю и $12 за месяц читались одинаково. Теперь `fromAlert` приводит сумму к месяцу по `ALERT_WINDOW_DAYS`; долг (просроченная оплата) показывается как есть с подписью «долг». Правила `waterfall_inversion`, `discrepancy`, `low_fill` получили оценку денег (оценочные помечены `payload.estimate`), `free_places` — эффект по медиане занятого места сайта. Карточка показывает строку доказательств из `evidence`, страница сайта — свои алерты с действием и «Принято к сведению» и блок «Гипотезы сайта»; бейдж «кандидат на снос» считается по порогам алерта №5 внутри формата, чтобы таблица и алерт не спорили.
