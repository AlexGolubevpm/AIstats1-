# 0012. Каталог мест фиксированный и одинаковый для всех сайтов; зоны ADOK привязываются по типу

- Статус: принято; заменяет [ADR 0010](0010-placements-from-zones.md)
- Дата: 2026-10-07

## Контекст

ADR 0010 пополнял каталог мест каждым новым названием зоны AdSpyglass. Оказалось, что зоны в ADOK названы с префиксом сайта: «GX_NTV_A», «HS_OutStream», «GXhub_Slider». Каталог превратился в колонку на каждую зону каждого сайта (GX_NTV_A, GX_OutStream, HS_InPP…), по одной зоне в колонке, и сетка «места × сайты» потеряла смысл: одно и то же место на разных сайтах стояло в разных колонках.

## Решение

1. Каталог — фиксированный список владельца, одинаковый для всех сайтов: Tablink 1–3, Underplayer, Video link 1–2, Under bar, Above bar, Welcome bar, Video pause banner, Pop, Slider, NTV A, NTV B, Footer A–D, OutStream, InVideo, Push. Новые места добавляются только вручную кнопкой «Добавить формат».
2. Зона привязывается по **типу** в названии: префикс сайта (короткий буквенно-цифровой до `_`) отбрасывается, остаток сопоставляется с правилами (`ZONE_RULES` в `domain/inventory.ts`): `NTV_A|ntv_1 → NTV A`, `Footer_B|footer_2 → Footer B`, `POP…|Popunder → Pop`, `InPP|push → Push`, `OutStream`, `InVideo|preroll|vast`, `Slider`, `Tablink_N`, `Underplayer`, `Video_link_N`, `Under/Above/Welcome bar`, `Video pause`. Запасной путь — совпадение слов названия места целиком.
3. Зона, тип которой правила не знают, остаётся «без формата» до ручной привязки в панели зон сайта. Каталог от неё не растёт.
4. Миграция удаляет места, созданные по ADR 0010 (без дилов и ручных отметок), снимает с их зон привязку; при старте воркера зоны привязываются заново по типу.

## Альтернативы

- **Нормализовать имя и создавать место из «типа».** Тип «InPP» или «NTV_A» дал бы колонки «Inpp» и «Ntv A» вместо списка владельца; список владельца первичен.
- **Привязывать только вручную.** 249 зон руками не привяжут.
