# ADR 0020. План на месяцы вперёд: темп ротации, дилы по датам, статьи, сценарий роста

Статус: принято · 2026-10-30

## Контекст

`/forecast` отвечал только «чем закончится текущий месяц». Владелец хочет планировать экономику на месяцы вперёд: видеть выручку, расход и маржу следующих месяцев, заранее вносить фикс-дилы будущих периодов и плановые статьи.

## Решение

1. Вид «На месяцы вперёд» на `/forecast` с горизонтом 3 / 6 / 12 месяцев (`monthsForecast`, чистый расчёт — `projectMonths` в `src/lib/forecast.ts`).
2. **Ротация без прямых дилов.** Темп будущих месяцев берётся по `revenue_mediated`, а прямые (`DIRECT`) дилы прибавляются по своим датам. Иначе закончившийся дил продолжал бы «приносить» в будущем, а новый — не появлялся бы. Дилы через ADOK остаются в темпе: их деньги приходят в выручке AdSpyglass.
3. **Дилы заводятся заранее** обычной формой с датой начала в будущем; новых статусов нет. До старта начисления нет (`forecastDeals` идёт до сегодня). Флэт считается точно (`flatPerDay`), за 1000 загрузок / CPM — по начислениям дила за последние дни или, если их ещё нет, оценкой по загрузкам (показам) его сайтов.
4. **Черновики** — «в переговорах»: показаны отдельно, в итог входят только по переключателю сценария.
5. **Рост — параметр владельца** (рост ротации и расхода, % в месяц, сложный по месяцам; по умолчанию 0). Как и в ADR 0008, модель тренд не придумывает.
6. **Опер. расходы** — введённые на месяц (`OpexEntry` уже принимал будущие месяцы); пустой месяц повторяет последний месяц с записями, с пометкой — постоянные расходы не надо вводить на каждый месяц, чтобы план не врал.
7. **Плановые статьи** — новая таблица `PlanItem` (месяц, доход/расход, сумма, сайт, заметка): то, чего нет ни в темпе, ни в дилах (новый сайт, закупка трафика, разовый платёж). Только план, в факты не пишутся; каждое изменение — в `AuditLog`. Прошлые месяцы не принимаются.
8. MCP `get_forecast` отдаёт те же строки месяцев.

## Последствия

- В демо-данных появился разрез по источникам трафика (без него ни один день не «полный», и темп пуст); выручка источника в демо — 0, расход идёт по ставкам CPU.
- План грубый по построению: один темп на месяц, без сезонности. Точность растёт вместе с данными и с тем, насколько честно заведены дилы и статьи.
- Тесты: unit `projectMonths` / `dealMonthAmount`; int `monthsForecast` (темп без прямых дилов, будущий и закончившийся дил, оценка CPM, черновики, рост, опер. расходы с переносом, статьи с аудитом, текущий месяц), MCP; E2E вида.
