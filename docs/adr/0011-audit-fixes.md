# 0011. Решения аудита статистики: RPM по измеренным сайто-дням, частичная оплата, пауза дила, счётчик по местам

- Статус: принято
- Дата: 2026-10-06

## Контекст

Аудит отчётов (см. `docs/product/12-analytics-gaps.md`, раздел «Аудит 06.10») нашёл несколько мест, где цифра на странице не соответствовала смыслу метрики. Часть исправлений — просто баги; четыре ниже меняют правила и зафиксированы здесь.

## Решения

1. **RPM на уника** = выручка / уники × 1000, но в числителе только выручка сайто-дней, за которые Метрика посчитала уников. Иначе один сайт без Метрики удваивал RPM сети: его выручка в числителе есть, уников в знаменателе нет. Для бандлов — то же.
2. **Частично оплаченный счёт** (`PARTIAL`) остаётся «выставлено» на полную сумму счёта. Раньше дни становились «подтверждено» на оплаченную часть, и выручка проседала на остаток, пока его не доплатят. Остаток виден в дебиторке; «подтверждено» — при полной оплате или списании.
3. **Дил на паузе** не начисляется с дня паузы (дата — запись `status → PAUSED` в журнале изменений). Раньше флэт-дил на паузе продолжал приносить прогнозную выручку каждый день.
4. **Счётчик дила без зоны** (`ASG_ZONE`): для CPM-дилов без гео-скоупа — зоны AdSpyglass, стоящие на местах дила на сайте (показы зон складываются); для дилов «за 1000 загрузок» и дилов со скоупом — загрузки сайта по странам, как раньше: одна загрузка страницы — одна единица, сколько бы зон на ней ни стояло, а у зон нет страны. Первая версия применяла зоны ко всем дилам и дала ×N загрузок у дила на N местах (06.10 — скачок до $11k).
5. **Счёт за один сайт** закрывает прогноз только этого сайта: раньше `covered(date)` не смотрел на сайт периода и стирал прогноз остальных сайтов дила.
6. **Гео-таблица** раскладывает деньги «без страны» по каждому сайту (как матрица), а не по всей сети; загрузки и уники строки `ZZ` переезжают вместе с деньгами.

## Альтернативы

- Для частичной оплаты — две строки на день (оплачено / остаток). Ключ `FactFixDeal` — (день, дил, сайт, страна), вторая строка потребовала бы смены схемы ради косметики в KPI «Подтверждено».
- Пауза по дате из формы, а не из журнала. Журнал уже пишется при каждой смене статуса; отдельное поле — дублирование.

## Дополнение 2026-10-07: введённые периоды пересчитываются каждым прогнозом

**Проблема.** Сумма введённого периода распределялась по счётчику один раз — при вводе. Период, внесённый до того, как ADOK отдал данные за его дни, застывал: вся сумма лежала на единственном дне с данными, а при отсутствии счётчика — целиком на последнем дне периода (так появился «$11k за один день» по флэт-дилу).

**Решение.** `forecastDeals` после расчёта прогноза вызывает `distributePeriod` для каждого введённого периода, пересекающего окно, — распределение всегда соответствует текущим счётчикам. При пустом счётчике сумма делится ровно по ячейкам день × сайт (вес 1), как у флэта. Данные периодов (суммы, статусы) не меняются — только их раскладка по дням.

## Дополнение 2026-10-07: источник правды для начислений — состав и срок дила

**Проблема.** Вьюха `v_site_geo_daily` суммирует все строки `FactFixDeal` дила с `billedVia = DIRECT`, а страница сайта показывала только активные дилы со строкой `DealSite`. Строки переживали удаление сайта из дила, сдвиг дат, завершение дила с запланированной более поздней датой конца, коррекцию периода с сужением дат и черновики. Сайт получал тысячи долларов «фикса», которого на его странице не было.

**Решение.** `reconcileDealFacts` в каждом прогнозе (ночь, старт воркера, сохранение, «Пересчитать прогноз») удаляет строки вне дила: сайт не в `DealSite`, день до `startsAt`, прогнозный день после фактического конца, строки superseded-версий периодов, строки черновиков. `distributePeriod` не раскладывает период на сайт, которого нет в диле. «Завершить» ставит `endsAt = min(endsAt, сегодня)`. Страница сайта показывает все дилы с начислениями за период с бейджами статуса. Readiness-проверка 11 считает осиротевшие строки.

**Отклонено.** Фильтровать `DealSite`/статус прямо во вьюхе: это спрятало бы деньги уже выставленных периодов по завершённым дилам и не объяснило бы, откуда сумма; чистить данные надёжнее, чем маскировать.
