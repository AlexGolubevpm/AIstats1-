# 0004. Два факта выручки AdSpyglass и признак биллинга дила

- Статус: принято
- Дата: 2026-09-23

## Контекст

В спецификации один `FactRevenue`, где гео-строки имеют `zoneId = null`, а зонные — `countryCode = 'ZZ'`. Любой запрос, который забыл про это условие, складывает два разреза одних и тех же денег. Кроме того, часть фикс-дилов оплачивается через AdSpyglass и уже присутствует там как сетка `own_deals`.

## Решение

- `FactRevenueGeo` (дата × сайт × сетка × страна × девайс) и `FactRevenueZone` (дата × сайт × зона, формат берётся из зоны). Выручка сайта и сети — только из гео-факта; зонный — для зон и форматов.
- У `Deal` поле `billedVia: DIRECT | VIA_ASG`. В `v_site_geo_daily` прямая выручка (`revenue_direct`) — только от `DIRECT`; `VIA_ASG`-дилы считаются для счётчиков, множителя и дебиторки, но в выручку второй раз не попадают.
- Роль `mcp_reader` — `NOLOGIN`; приложение переключается на неё через `SET LOCAL ROLE` в read-only транзакции. Отдельный пароль не нужен.

## Альтернативы

- Один факт с соглашением о `null`/`ZZ` — ошибка задвоения ждёт каждый новый запрос и каждый SQL из MCP.
- Отдельный логин для `mcp_reader` — ещё один секрет на сервере без выигрыша в изоляции.

## Последствия

- Вьюхи `v_zone_daily` и `v_format_daily` строятся из `FactRevenueZone`, остальные — из `FactRevenueGeo`.
- Контрольная сверка «зоны vs гео» по сайту остаётся тестом данных.
