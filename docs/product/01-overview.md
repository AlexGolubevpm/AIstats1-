# 01. Обзор продукта

> Статус: утверждено к разработке · Источник требований: [`../tubestat-spec.md`](../tubestat-spec.md)

## Зачем

TubeStat — внутренний дашборд **маржи** по сети из ~40 тьюб-сайтов. Трафик покупается, поэтому выручка без цены закупки того же гео ничего не говорит. Каждый экран отвечает на один вопрос: *где мы зарабатываем, где теряем и что крутить дальше*.

## Кто пользуется

| Роль | Что делает | Как часто |
| --- | --- | --- |
| Владелец сети | Смотрит маржу по сети и бандлам, решает, какие гео закупать | Каждый день, 5–10 минут |
| Оптимизатор монетизации | Разбирает сайт: зоны, форматы, сетки, дискрепанси; ставит биды в AdSpyglass руками | Каждый день, основная работа |
| Менеджер фикс-дилов | Заводит дилы, вносит цифры рекламодателя, подтверждает оплату | Несколько раз в неделю |
| Claude через MCP | Отвечает на вопросы по тем же данным | По запросу |

Пользователей мало (1–3 человека), поэтому ролей в системе нет: один пароль на всё. Интерфейс рассчитан на ежедневную работу, а не на презентацию.

## Ключевые сценарии

1. **Утренняя сверка.** Открыть `/`, увидеть маржу за вчера и неделю, красные бандлы и новые алерты.
2. **Решение по закупке.** `/geo` или гео-блок бандла → фильтр «только убыточные» → снизить закупку или поднять флор.
3. **Разбор сайта.** `/sites/[domain]` → вкладка «Зоны» → найти невидимые и мёртвые зоны → поправить вёрстку.
4. **Финансы по тьюбам.** `/finance` → P&L по каждому сайту: подтверждённая выручка, прогноз, расход, маржа.
5. **Фикс-дилы.** `/deals` → завести дил → вносить показы рекламодателя и суммы из инвойсов → подтвердить платёж.
6. **Вопрос к данным.** Спросить Claude: «покажи убыточные гео JAV-бандла за неделю». Ответ придёт через MCP.

## Принципы (не обсуждаются)

1. **Маржа, а не выручка.** Любая цифра дохода показывается рядом с расходом там, где расход известен (сайт × страна и выше).
2. **Own deals живут отдельно.** AdSpyglass не включает их в зонный и форматный разрезы, поэтому держим их в `FactFixDeal` и склеиваем во вьюхах с флагом источника.
3. **Два счётчика показов.** Свои показы и показы рекламодателя видны всегда, дискрепанси считается.
4. **Отчётная ≠ подтверждённая выручка.** Пока платёж не пришёл, это прогноз, и UI показывает его пунктиром.
5. **Сырьё до трансформации.** Каждый ответ API сохраняется в S3 до записи в базу. Пересчёт метрик не требует повторного обхода API.
6. **Всё состояние в URL.** Ссылка на срез открывается у другого человека в том же виде.
7. **Только чтение внешних систем.** Система рекомендует, биды ставит человек.

## Границы первой версии

Нет: ролей и мультиаккаунтов, real-time (минимум — сутки), автоизменения бидов, мультивалютности (всё в USD), почасовых разрезов, миграции истории старше 30 дней.

## Глоссарий

| Термин | Значение |
| --- | --- |
| Тьюб, сайт | Один домен сети. Сущность `Site` |
| Бандл | Группа сайтов (JAV, Hentai, Gay…). Сайт может быть в нескольких бандлах |
| Сетка, партнёр | Рекламная сеть внутри AdSpyglass (в API — `broker`). Own deals — тоже «сетка» |
| Зона, спот | Рекламное место на сайте (`Zone`), у него один формат |
| Формат | POPUNDER, BANNER, NATIVE, SLIDER, OUTSTREAM, INVIDEO, INPAGEPUSH |
| Page load (hit) | Загрузка страницы с рекламным кодом, знаменатель большинства метрик |
| Фикс-дил | Прямая сделка с рекламодателем по фиксированной цене, мимо аукциона AdSpyglass |
| Закупка | Покупной трафик (TubeCrown, TubeTraffic/ixxx), единственная статья расхода |
| Рестейт | Правка системами-источниками цифр за прошлые дни; перетягиваем окно T-1…T-4 |
| Прогноз / подтверждено | Выручка до и после фактической оплаты |
