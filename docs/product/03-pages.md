## `/` — Сводка по сети

**Вопрос:** сеть в плюсе? что сломалось со вчера?

| Блок | Содержимое |
| --- | --- |
| KPI | Выручка · Расход · Маржа · **ROMI** (шире) · Уники · RPM на уника. Дельта к предыдущему равному периоду; спарклайнов нет — линия без оси ничего не говорит. Если в периоде есть дни с выручкой, но без разреза по источникам (расход не загружен), на «Расход» и «ROMI» — ⚠ с текстом «Расход не загружен за N из M дн.» |
| Выручка по сеткам | Stacked bar по дням: сегменты — сетки AdSpyglass (цвет из базы) и прямые фикс-дилы |
| Расходы | Stacked bar по дням: расход на трафик по источникам (TubeCrown, TubeTraffic, …) и операционные расходы по дням месяца |
| P&L | По дням: столбцы — выручка, расход на трафик, опер. расходы; линия — маржа после опер. расходов. Пустые дни — разрыв, не ноль |
| Бандлы | Таблица: Бандл · Сайтов · Уники · Выручка · Расход · Маржа · ROMI · RPM. Клик → `/bundles/[slug]`. Строка «Итого» считается **по сайтам сети**, а не суммой строк; под таблицей мелко: «Сумма по бандлам ≠ сети: 3 сайта входят в несколько бандлов» |
| Топ-движения | Два столбца по 5 сайтов: сильнее всего выросла и упала маржа к прошлому периоду |
| Алерты | Последние 5 critical и warning, ссылка «Все алерты» |

**Действия:** сменить период; кликнуть в бандл, сайт или алерт; экспортировать таблицу бандлов в CSV.

<a id="forecast"></a>
## `/forecast` — Прогноз

**Вопрос:** чем закончится месяц, если дальше будет как в последние дни?

Берётся текущий календарный месяц (`?month=YYYY-MM` — любой прошлый, там прогноз равен факту). Темп — среднее по последним N **полным** дням (вчера и назад; `?n=3|7|14`, по умолчанию 7; если полных дней меньше N — по тем, что есть, с предупреждением). Сегодняшний день неполный и прогнозируется как будущий. Формула и ограничения — [06](06-metrics.md#forecast).

| Блок | Содержимое |
| --- | --- |
| Переключатели | Динамика по 3 / 7 / 14 дням · предыдущий месяц · «Текущий месяц» |
| KPI | Прогноз выручки (факт + темп × оставшиеся дни) · Расход на трафик · Опер. расходы (известны на весь месяц из `OpexEntry`) · Маржа после опер. расходов · ROMI на расход на трафик · прошлый месяц. Дельты — к прошлому месяцу |
| По дням месяца | Каждый день месяца: сплошные столбцы — факт, светлые — прогноз; расход сплошной/пунктирной линией; линия накопленной маржи. Под графиком таблица дней: статус (факт / сегодня / прогноз), выручка, расход, опер., маржа, накоплено. В подписи — сколько выручки флэт-дилов впереди известно заранее |
| По сайтам | Факт с начала месяца · темп в день · прогноз месяца (по собственному темпу сайта) · маржа (прогноз, без опер. расходов) · прошлый месяц · дельта к нему. Клик → страница сайта |

<a id="recommendations"></a>
## `/recommendations` — Рекомендации

**Вопрос:** что сделать руками, чтобы заработать больше или перестать терять?

Один список всех рекомендаций по сайтам, гео, зонам, сеткам, фикс-дилам, источникам трафика и форматам. Два источника: **алерты** (действие правила — «Что сделать», сообщение — «почему») и **правила по таблицам** за 7 и 30 дней ([06 → Рекомендации](06-metrics.md#recommendations)). Про один и тот же объект алерт важнее правила. Сортировка: критичные, затем по сумме под риском.

| Блок | Содержимое |
| --- | --- |
| Чипы | Все · Сайты · Гео · Зоны · Сетки · Фикс-дилы · Источники · Форматы (`?scope=`) с числом пунктов; бандлы (`?bundle=`) |
| Список | Заголовок (ссылка на разрез, где это видно) · область · пометка «алерт» · почему (цифры) · **Что сделать** · сумма под риском |

Система только рекомендует: ни флор, ни waterfall, ни зоны из дашборда не меняются.

## `/geo` — Гео по сети

**«Без страны» (код `ZZ`).** ADOK не отдаёт разрез «источник трафика × страна», поэтому расход источников ([ADR 0006](../adr/0006-traffic-source-cost-revshare.md)), флэт-дилы и почасовые итоги сайта без стран лежат в коде `ZZ`. В таблицах гео (`/geo`, сайт → Гео, бандл → Гео, матрица сайт × страна) эти деньги **раскладываются по странам пропорционально загрузкам** как оценка (тултип у колонки «Расход»); строка «Без страны» остаётся только у сайта, у которого стран нет вовсе, и без ROMI. Алерт «Убыточное гео» код `ZZ` не рассматривает. [ADR 0008](../adr/0008-forecast-and-geo-cost-allocation.md).

**Вопрос:** какие страны закупать дальше?

| Блок | Содержимое |
| --- | --- |
| KPI | Стран с расходом · Убыточных · Расход в убыточных гео · Средний ROMI |
| Таблица | Страна · Тир · Сайтов · Уники · Page loads · Выручка · Расход · Cost/unique · Маржа · ROMI · Rev/1000 loads. Фильтры: «только убыточные», «только с расходом». Расход без страны раскладывается **по каждому сайту** на его страны (расход сайта A не попадает в страны сайта B), вместе с загрузками и униками строки «без страны»; такие строки помечены бейджем «оценка», Cost/unique у них не считается. Тепловая заливка ROMI — относительно ROMI итога, не среднего по строкам |
| Матрица | Сайт × страна, ячейка — ROMI с тепловой заливкой; топ-12 стран по расходу (расход без страны разложен по сайту) |
| Нераспознанные | Если есть строки с `XX` — плашка «N строк без страны» → `/settings/integrations#geo` |

Стоп-лист — фильтр «только убыточные». Он шире алерта №1: алерт смотрит только на расход, заведённый по странам (CSV, ставки), а таблица — ещё и на расход источников, разложенный по загрузкам как оценка.

<a id="inventory"></a>
## `/inventory` — Форматы

Сетка «сайты × места на сайте»: сколько каждый формат заработал на каждом сайте за период и чем он занят. Места — каталог `Placement`: по умолчанию Tablink 1–3, Underplayer, Video link 1–2, Under bar, Above bar, Welcome bar, Video pause banner. Кнопка «Добавить формат» добавляет колонку всем сайтам. Период — переключатель в шапке (`?preset=`, по умолчанию 7 дней).

**Деньги в ячейке** = выручка зон AdSpyglass этого сайта, привязанных к месту (`FactRevenueZone`), + выручка фикс-дилов с этим местом на этом сайте (`FactFixDeal`, равномерно по дням и сайтам; дил на нескольких местах одного сайта делит факты сайта поровну между ними) — и прямых, и «через AdSpyglass»: own deals в зонный разрез ADOK не входят, поэтому их деньги в ячейку попадают только из дила. Итоги: по строке — сайт, по колонке — место (в шапке колонки, вместе с числом свободных), в последней строке — все показанные сайты. Итог сети — по сайтам, не суммой бандлов.

**Откуда колонки.** Каталог мест — фиксированный список владельца, одинаковый для всех сайтов ([ADR 0012](../adr/0012-canonical-places.md)): Tablink 1–3, Underplayer, Video link 1–2, Under bar, Above bar, Welcome bar, Video pause banner, Pop, Slider, NTV A/B, Footer A–D, OutStream, InVideo, Push (+ добавленные кнопкой). Зоны AdSpyglass называются с префиксом сайта («GX_NTV_A», «HS_OutStream», «GXhub_Slider»); префикс отбрасывается, а тип после него определяет место: NTV_A → NTV A, footer_1 → Footer A, POP player → Pop, InPP → Push. Зона, тип которой правила не знают, остаётся «без формата» до ручной привязки; в шапке колонки — число зон в ней. Кнопка «N зон» у сайта открывает панель: все зоны сайта (название, тип ADOK, выручка за период) и выбор места для каждой — так зону можно перенести в другую колонку. Ручная привязка хранится в `Zone.placementSlug` и ночным `derive` не перетирается; «— без формата —» снимает её до следующего сопоставления.

**Бандлы.** Выбор «Бандл» (`?bundle=`) оставляет сайты бандла; «Группировать по бандлам» (`?group=bundle`) делит сетку на блоки с подытогом по бандлу (сайт из двух бандлов стоит в обоих блоках, сайты вне бандлов — в блоке «Без бандла»). Общий итог при группировке всё равно считается по сайтам, по одному разу. Фильтры сочетаются с «Только со свободными» (`?free=1`).

Цвет ячейки — состояние, решается так (`domain/inventory.ts → resolvePlace`), первое подходящее:

| Состояние | Откуда |
| --- | --- |
| **Фикс** | Активный дил «напрямую нам», у которого отмечено это место на этом сайте (`DealPlace`: чипы в форме дила или «Добавить фикс-дил» в панели ячейки) |
| **Own deal ASG** | Активный дил «через AdSpyglass» с этим местом; или без дила — место выкупает прямая сетка (`SitePlacement.networkId`) |
| Отмечено вручную | Панель ячейки: состояние (CPA, ротация, свободно, «нет места»), заметка и «место выкупает сетка»; сетка без состояния → own deal для прямой сетки, ротация для медиации |
| **Ротация ASG** | Зона AdSpyglass сайта, привязанная к месту — по названию или вручную в панели зон |
| **Свободно** | Ничего из перечисленного |

В ячейке — выручка за период; если её нет — рекламодатель дила (при нескольких — «N фикс-дила»), название сетки или короткое состояние («ASG», «Own», «CPA», «свободно»). В тултипе — кто стоит, за сколько, с какого по какое число и сколько дней осталось. Точка в углу ячейки — дил заканчивается в течение недели.

**Панель ячейки** (клик): «Фикс-дилы на этом месте» — список со ссылками на карточки и кнопкой «Убрать с места» (дил остаётся на сайте, место освобождается); «Добавить фикс-дил» — поиск по активным и приостановленным дилам, мультивыбор, «Привязать» (дил, которого не было на сайте, добавляется на сайт), ссылка «Новый дил на этом месте» открывает форму с отмеченным местом; «Состояние и сетка» — какая сетка выкупает место, ручное состояние и заметка.

**Таблица «Фикс-дилы» под сеткой** — все дилы из раздела `/deals` (активные, на паузе и закончившиеся за последние 30 дней): Места (бейдж «не указано», если у дила нет ни одного места) · Дил (с бейджем сайтов) · Кто стоит · Сайтов · За сколько · Модель · С · По · Осталось дней · Статус. Сортировка по умолчанию — заканчивающиеся раньше сверху, бессрочные после, закончившиеся внизу. Фильтры: «Заканчиваются за 7 дней», «Без места». Строки с ≤ 3 днями подсвечены. Клик по строке — карточка дила.

## `/alerts` — Алерты

**Вопрос:** что требует действия прямо сейчас?

- Группы по уровню: Critical → Warning, внутри — по правилу с суммой денег под риском. В группе первые 5 алертов (по сумме под риском), остальные — под «Ещё N».
- Фильтры: бандл, правило, «показать скрытые». «Вернуть» снимает скрытие.
- Каждый алерт: иконка уровня, заголовок, текст с цифрами и рекомендуемым действием, ссылка на разрез («Открыть гео JP на japan-whores.com»), дата первого срабатывания, сколько дней подряд.
- **«Принято к сведению»** скрывает алерт на 30 дней. Если за это время ситуация ухудшится (деньги под риском вырастут больше чем вдвое), алерт вернётся сам.

Правила — в [06-metrics](./06-metrics.md#alerts).

## `/login`

Одно поле пароля и кнопка. После 5 неверных попыток с одного IP — пауза 15 минут. Редирект на исходный URL после входа.
