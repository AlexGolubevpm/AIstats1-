# 04. Финансы по тьюбам и фикс-дилы

Два связанных раздела:
- `/finance` показывает, сколько денег принёс каждый тьюб;
- `/deals` — место, где вносятся деньги, которых нет в AdSpyglass.

Правило разделов: **любая сумма имеет статус** — прогноз, выставлено или подтверждено. Статус виден везде, где сумма показывается.

---

<a id="finance"></a>
## `/finance` — Финансы по тьюбам

**Вопрос:** сколько каждый тьюб реально заработал за месяц, сколько ещё должно прийти и где мы в минусе?

Это бухгалтерский взгляд на те же данные. Период по умолчанию — **текущий месяц** (пресеты: этот месяц, прошлый месяц, квартал, произвольный), потому что оплаты и счета живут месяцами.

### Статусы выручки

| Статус | Откуда | Как выглядит |
| --- | --- | --- |
| Прогноз | AdSpyglass `broker_income` за незакрытый месяц; фикс-дил по ставке × наш счётчик | Пунктирная рамка ячейки, серый текст суммы, подпись «прогноз» в тултипе |
| Выставлено | Фикс-дил: рекламодатель прислал цифры, выставлен инвойс | Обычный текст, иконка документа |
| Подтверждено | Деньги пришли: оплата фикс-дила или выплата AdSpyglass за месяц | Обычный текст, иконка галочки |

### Блоки

**1. KPI (одна строка)**

`Выручка всего` · `Подтверждено` · `Ожидается` (прогноз + выставлено, не оплачено) · `Расход` · `Маржа` · `ROMI` · `Дебиторка просрочена` (выставлено и не оплачено дольше срока оплаты)

Под `Выручка всего` — тонкая полоса из трёх сегментов: подтверждено, выставлено, прогноз.

**2. График «Структура выручки»**

Stacked bar по дням (или по месяцам, если выбран период больше 62 дней). Сегменты: AdSpyglass, фикс-дилы подтверждённые, фикс-дилы ожидаемые (штриховка). Линия поверх — расход. Цвета берутся из сеток: own deals — зелёный.

**3. Таблица «P&L по тьюбам» — главная**

| Колонка | Тип | Примечание |
| --- | --- | --- |
| Сайт | site | Домен + бейджи бандлов |
| AdSpyglass | money | Медиированная выручка; статус по месяцу |
| Фикс-дилы | money | Сумма по всем дилам сайта; мини-полоса «подтв./выставл./прогноз» |
| Выручка | money | Итого |
| Расход | money | Сумма закупки; тултип — разбивка по источникам (TubeCrown, TubeTraffic) |
| Маржа | money + цвет | |
| ROMI | percent + цвет | Заливка по правилу ±20% от среднего |
| Доля маржи | share | Полоса-фон |
| Полнота | status | Иконки: ⚠ расход не заведён за N дней, ⚠ нет данных Метрики, ⚠ дил без цифр рекламодателя |

- Строка кликается и раскрывается в подтаблицу по месяцам и источникам выручки/расхода.
- Итог закреплён снизу и считается по сайтам, а не по бандлам.
- Фильтры: бандл, «только убыточные», «только с неполными данными».
- Экспорт: CSV таблицы и «Отчёт за месяц» (CSV с разбивкой сайт × источник × статус).

**4. Выплаты AdSpyglass**

Карточка по месяцам (последние 6): отчётная сумма за месяц · получено · расхождение · статус («месяц идёт» / «ждём выплату» / «подтверждено»). Действие **«Внести выплату»**: сумма и дата. Система распределяет полученную сумму по сайтам пропорционально отчётной выручке и помечает месяц как подтверждённый. Расхождение больше 2% подсвечивается `--warning`.

**5. Дебиторка по фикс-дилам**

Короткая таблица: рекламодатель · дил · период · выставлено · срок оплаты · дней просрочки. Ссылка «Все оплаты» ведёт на `/deals?tab=payments`.

### Правила расчёта

- Выручка тьюба = AdSpyglass + фикс-дилы. Own deals, которые приходят через AdSpyglass в гео-разрезе, **не задваиваются**: у них источник `own_deals`, и если на тот же дил заведён `Deal` с `source = ASG`, берём цифру только из одного места (см. раздел «Источник своего счётчика» ниже).
- Расход известен только на уровне сайт × страна × день. ROMI на `/finance` считается по сайту целиком.
- Если за часть периода расход не заведён, ROMI помечается «неполный», и в тултипе видно, какие дни пустые.

<a id="deals"></a>
## `/deals` — Фикс-дилы

**Вопрос:** какие прямые сделки идут, сколько они принесли и где рекламодатель нам должен?

Сюда попадают сделки, которые **не проходят через аукцион AdSpyglass**: прямой код рекламодателя на сайте, спонсорский баннер, флэт за место. Их выручки в AdSpyglass нет вовсе или она там неполная.

### Модель сделки

| Поле | Значение |
| --- | --- |
| Рекламодатель, название | Свободный текст; рекламодатель — справочник с автодополнением |
| Формат | `AdFormat` |
| Сайты | Один или несколько; опционально — конкретные зоны |
| Гео-скоуп | Список стран, тир (1/2/3) или «все, кроме…» |
| Модель оплаты | **За 1000 загрузок** (по умолчанию) · за показ рекламодателя (CPM по его счётчику) · за свой показ (CPM по нашему) · флэт в сутки · флэт за период |
| Цена | USD, 4 знака для CPM, 2 для флэта |
| Период | Дата начала, дата конца (или бессрочно) |
| Биллинг | Период счёта (месяц / неделя / весь срок) и срок оплаты в днях (net 15/30) |
| Источник своего счётчика | `ASG_ZONE` — зона в AdSpyglass (показы и загрузки берём оттуда) · `METRIKA` — просмотры страниц из Метрики как загрузки · `MANUAL` — вводим руками |
| Статус | Черновик · Активен · На паузе · Завершён |
| Заметки, контакт | Текст |

«За 1000 загрузок» стоит по умолчанию: это единственная модель, где мы сами контролируем знаменатель.

### Жизненный цикл денег по дилу

```
каждый день     ─►  ПРОГНОЗ     ставка × наш счётчик, пишется ночным джобом в FactFixDeal
конец периода   ─►  к вводу     период попадает в очередь «Нужно внести данные»
цифры пришли    ─►  ВЫСТАВЛЕНО  введены показы рекламодателя и сумма счёта
деньги пришли   ─►  ПОДТВЕРЖДЕНО введена сумма и дата оплаты
                    ├─ сумма меньше выставленной → остаток «открыт» или «списан» с причиной
                    └─ спор → статус «спор», сумма не входит в подтверждённую выручку
```

### Страница `/deals`

Три вкладки (`?tab=`):

**Дилы** (по умолчанию)

| Колонка | |
| --- | --- |
| Рекламодатель / название | Ссылка на карточку |
| Формат, модель оплаты, цена | |
| Сайты | До 3 доменов + «ещё N» |
| Прогноз за период | money, пунктир |
| Выставлено / Подтверждено | money |
| Множитель | impsReported / impsOwn; > 1.5× — `--warning` с тултипом «рекламодатель засчитывает в N раз больше показов» |
| Статус | Бейдж |

Действия: «Новый дил», фильтры по статусу и рекламодателю, архив завершённых.

**Нужно внести** — очередь работы. Каждая строка — закрытый период биллинга без цифр рекламодателя или счёт без оплаты после срока. Сортировка: сначала просроченные, затем по сумме прогноза. Кнопка **«Внести»** открывает форму ввода прямо в строке.

**Оплаты** — реестр дебиторки: выставлено, оплачено, остаток, срок, просрочка по корзинам 0–30 / 31–60 / 60+ дней. Итог по рекламодателю.

### Карточка `/deals/[id]`

- **Шапка:** рекламодатель, название, статус, модель оплаты и цена, кнопки «Редактировать условия», «Пауза», «Завершить».
- **KPI:** Прогноз · Выставлено · Подтверждено · Остаток к оплате · Множитель показов · Эффективный CPM (подтверждено / наши показы × 1000).
- **График:** по дням — наши показы (линия) и показы рекламодателя (линия, появляется после ввода), столбцы — выручка по статусам.
- **Периоды:** таблица периодов биллинга — Период · Наш счётчик · Счётчик рекламодателя · Дискрепанси · Прогноз · Выставлено · Оплачено · Статус · действия (Внести / Подтвердить оплату / Исправить).
- **История:** журнал изменений условий и сумм: кто, когда, что было, что стало, причина.

### Форма «Внести данные за период»

Открывается боковой панелью (Sheet), не модалкой: таблица под ней остаётся видна для сверки.

```
Период            [01.09.2026 — 30.09.2026]      (подставлен период биллинга)
Детализация       (•) Итого за период  ( ) По сайтам  ( ) По дням — вставка CSV

Наш счётчик       1 284 320 показов · 2 910 004 загрузок       (только чтение)
Показы рекламод.  [ 1 402 110 ]        → дискрепанси −9.2%  ✓ в пределах ±10%
Сумма к оплате    [ $1 121.69 ]        авторасчёт: 1 402 110 × $0.80 / 1000 = $1 121.69
                  ☐ Сумма отличается от расчёта — причина: [____________]
Номер счёта       [ INV-2026-09-014 ]
Срок оплаты       [ 30.10.2026 ]       (из условий дила: net 30)

Предпросмотр: прогноз $1 027.46 → выставлено $1 121.69 (+$94.23, +9.2%)
                                                 [Отмена]  [Сохранить — Выставлено]
```

Поведение:
- Сумма считается автоматически по модели оплаты. Ручное изменение требует галочки и причины, а в истории появляется пометка «переопределено».
- Режим «По сайтам» — строка на каждый сайт дила, то же для гео, если дил считается по гео.
- Режим «По дням» — поле вставки CSV `date, site, country, imps_reported, amount` с предпросмотром: сколько строк распознано, какие сайты/страны не смаплены, итоговая сумма.
- Период не может пересекаться с уже внесённым для того же дила и сайта — ошибка валидации показывается у поля периода.
- Черновик формы автосохраняется в браузере до отправки.

### Форма «Подтвердить оплату»

Поля: сумма получена (по умолчанию = выставлено), дата, комментарий. Если сумма меньше, появляется выбор: «Остаток ожидается» или «Списать остаток» с обязательной причиной. После сохранения суммы по дням переходят в статус «Подтверждено».

### Как суммы периода раскладываются по дням

Выставленная или оплаченная сумма за период распределяется по дням, сайтам и гео **пропорционально нашему счётчику** той модели, по которой считается дил: загрузки для «за 1000 загрузок», свои показы для CPM. Для флэта — равномерно по дням. Так `/finance`, страницы сайтов и MCP видят одну и ту же дневную грануляцию, а сумма за период сходится до цента: остаток округления уходит в последний день.

Приоритет для каждого дня: подтверждено > выставлено > прогноз.

### Исправления

Выставленные и подтверждённые суммы не удаляются. «Исправить» создаёт новую версию с обязательной причиной; старая остаётся в истории. Удалить можно только черновой дил без внесённых периодов.
