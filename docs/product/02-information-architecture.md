# 02. Информационная архитектура

## Карта страниц

```
/                          Сводка по сети
/finance                   Финансы по тьюбам (P&L по сайтам, прогноз vs подтверждено)
/bundles                   Список бандлов → /bundles/[slug]
/bundles/[slug]            Страница бандла
/sites                     Список сайтов → /sites/[domain]
/sites/[domain]            Страница сайта (рабочий экран оптимизатора)
/geo                       Все гео по сети: маржа, стоп-лист
/deals                     Фикс-дилы: список, ввод данных, подтверждение оплат
/deals/[id]                Карточка дила
/alerts                    Активные алерты
/settings/sites            Сайты и привязка ID
/settings/bundles          Бандлы и их состав
/settings/costs            Ставки закупки и импорт расхода
/settings/networks         Сетки: цвет, тип, порядок в легенде
/settings/integrations     Токены, статус ингеста, ручной перезапуск, нераспознанные гео
/settings/access           Пароль, MCP-токен
/login                     Вход по паролю
```

Отличия от спецификации (обоснование в [ADR-0002](../adr/0002-deals-top-level-page.md)):
- Фикс-дилы — отдельный раздел `/deals`, а не `/settings/deals`. Ввод цифр рекламодателя и подтверждение оплат — регулярная работа, а не настройка.
- Добавлена `/finance`: сводный P&L по тьюбам с разделением на прогноз и подтверждённую выручку.
- Добавлены списки `/bundles` и `/sites`, чтобы у навигации были точки входа, и `/settings/networks` для цветов сеток, которые лежат в базе.

## Навигация

Сайдбар 240px, сворачивается до 56px (только иконки, подписи в тултипах). Состояние свёрнутости хранится в `localStorage`.

```
┌──────────────────────┐
│ ◆ TubeStat           │
├──────────────────────┤
│ ▦ Сводка             │  /
│ $ Финансы            │  /finance
│ ◫ Бандлы         ▸   │  /bundles  (раскрывается списком бандлов с цветной точкой)
│ ▤ Сайты              │  /sites
│ ◎ Гео                │  /geo
│ ⇄ Фикс-дилы     (3)  │  /deals    (бейдж: дилы с неподтверждёнными периодами)
│ △ Алерты        (7)  │  /alerts   (бейдж: активные critical + warning)
├──────────────────────┤
│ ⚙ Настройки      ▸   │  /settings/*
├──────────────────────┤
│ ● AdSpyglass 14 мин  │  свежесть данных, жёлтая точка если > 2 ч,
│ ● Метрика    22 мин  │  красная — если последний IngestRun failed
│ ◐ Тема               │
└──────────────────────┘
```

Клик по индикатору свежести ведёт на `/settings/integrations`.

## Состояние в URL

Никакого глобального стора. Всё, что меняет видимые данные, живёт в `searchParams`:

| Параметр | Где | Пример |
| --- | --- | --- |
| `from`, `to` | все страницы с данными | `?from=2026-09-15&to=2026-09-21` |
| `preset` | вместо from/to | `yesterday`, `7d`, `30d`, `mtd`, `prev_month` |
| `by` | вкладки разреза | `?by=zones` |
| `sort`, `dir` | таблицы | `?sort=margin&dir=desc` |
| `page` | пагинация | `?page=2` |
| `f.*` | фильтры таблиц | `?f.loss=1&f.tier=1` |
| `split` | разбивка графика | `?split=formats` |
| `compare` | период сравнения | `prev` (по умолчанию), `yoy` не делаем в v1 |

Значение по умолчанию в URL не пишется, чтобы ссылки оставались короткими. Кнопка «назад» возвращает предыдущий срез.

## Состояния любой страницы с данными

| Состояние | Что видит пользователь |
| --- | --- |
| Загрузка | Скелетоны тех же размеров, что и контент. Без спиннеров на весь экран |
| Нет данных за период | `EmptyState` «Нет данных за выбранный период» + кнопка «Последние 7 дней» |
| Ингест не отработал | `EmptyState` с временем последнего успешного `IngestRun` и кнопкой «Перезапустить» |
| Фильтр ничего не нашёл | `EmptyState` «Ничего не найдено» + «Сбросить фильтры» |
| Ошибка запроса | Блок с текстом ошибки и «Повторить». Остальные блоки страницы продолжают работать |
| Частичные данные | Жёлтая плашка над графиком: «Метрика за 22.09 ещё не загружена», разрыв линии на графике |

## Доступ

Одна страница `/login` с паролем (`APP_PASSWORD`). После входа ставится httpOnly-cookie на 30 дней. Все страницы и `/api/*`, кроме `/api/health` и `/api/mcp`, закрыты. У `/api/mcp` своя авторизация по Bearer-токену.
