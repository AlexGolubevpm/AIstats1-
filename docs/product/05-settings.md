# 05. Настройки

Раздел `/settings`: слева вертикальное подменю, справа контент. Все изменения сохраняются сразу (инлайн-редактирование) или кнопкой в форме. Ни одно действие здесь не удаляет факты: архивирование скрывает, но история остаётся.

| Подраздел | Что настраивается |
| --- | --- |
| [Сайты](#sites) | Список тьюбов, привязка к AdSpyglass и Метрике, статус |
| [Бандлы](#bundles) | Группы сайтов, цвет, состав |
| [Закупка](#costs) | Ставки закупки по умолчанию и импорт фактического расхода |
| [Сетки](#networks) | Справочник рекламных сеток, цвета, тип |
| [Гео и тиры](#settingsgeo--гео-и-тиры) | Тиры стран 1–5, массовая вставка, журнал правок |
| [Интеграции](#integrations) | Токены, статус ингеста, ручной перезапуск, нераспознанные гео |
| [Доступ](#access) | Пароль приложения, MCP-токен |

---

<a id="sites"></a>
## `/settings/sites`

Таблица всех сайтов: Домен · Название · AdSpyglass ID · Счётчик Метрики · Бандлы · Статус · Дата запуска · Последний ингест (оба источника) · действия.

- **Добавление:** пустая строка в конце таблицы, без модалки. Обязателен домен и хотя бы один из двух ID.
- **«Проверить»** у строки: запрашивает оба API за вчера и показывает, пришли ли данные («AdSpyglass: 12 480 загрузок · Метрика: 3 211 уников»). Опечатка в ID видна сразу, а не через сутки пустого графика.
- **Импорт из AdSpyglass:** кнопка «Подтянуть сайты» берёт список `group_by=website` и предлагает добавить отсутствующие домены с уже заполненным ID.
- **Счётчик Метрики** обычно подбирается по домену на `/settings/integrations` → «Яндекс Метрика» (ниже); руками его вводят, когда на один домен приходится несколько счётчиков или у сайта уже стоит другой.
- **Статусы:** `ACTIVE` участвует везде · `PAUSED` не тянется ингестом, история видна · `ARCHIVED` скрыт из списков и итогов.
- **Массовые действия:** выделить строки → добавить в бандл / убрать из бандла / сменить статус.
- **Валидация:** домен уникален и приводится к нижнему регистру без `www.`; ID AdSpyglass уникален.

<a id="bundles"></a>
## `/settings/bundles`

Список: Название · Слаг · Цвет · Сайтов · Выручка за 30 дней.

- Редактирование состава — два списка рядом («В бандле» / «Остальные») с поиском и чекбоксами.
- Рядом с каждым сайтом — все его бандлы: пересечения должны быть на виду.
- Цвет — выбор из категориальной палитры; уже занятые цвета помечены.
- Слаг меняется с предупреждением: старые ссылки перестанут работать.

<a id="costs"></a>
## `/settings/costs`

**Блок «Ставки»** — таблица `CostRate`: Источник · Сайт (или «все») · Гео (или «все») · Модель (CPM / CPC / CPU / FLAT) · Ставка · Действует с · по.

- Новая ставка с той же областью автоматически закрывает предыдущую датой `validTo = validFrom − 1 день`.
- Разрешение конфликтов — от частного к общему: сайт + гео > сайт > гео > глобальная.
- Кнопка «Пересчитать расход» за выбранный период запускает джоб `costs:recalc` и показывает, сколько строк изменится.
- Предупреждение, если у активного сайта с трафиком нет ни одной применимой ставки.

**Блок «Источники трафика из AdSpyglass»** — источники из разреза `traffic_source` (создаются сами при ночной выгрузке): Название · Слаг · «Доля выручки в расход, %». Расход источника за день по сайту = сумма, которую ADOK показывает у источника как «выручку» (на деле — сколько заплачено источнику), × доля. По умолчанию 100%; Direct, Organic SE и No source — 0% (не закупка). Новый источник из ADOK помечен «доля не подтверждена» и даёт алерт №11, пока долю не сохранить (`CostSource.confirmed`). После сохранения доли расход по ревшаре за последние два месяца пересчитывается сразу; за более ранние — «Пересчитать расход» за нужный период. Ставки из блока «Ставки» к этим источникам не применяются; импорт CSV по-прежнему перекрывает.

**Блок «Импорт фактического расхода»**

- Загрузка CSV `date, domain, country, source, uniques, cost`. Опционально — подключённый Google Sheet (перенос из adkai).
- Предпросмотр до записи: строк распознано · доменов не найдено · гео не смаплено · итоговая сумма · сколько расчётных строк будет перекрыто.
- Импортированное всегда перекрывает расчётное по ставкам, в `FactCost.origin` пишется `IMPORT`.
- История импортов: файл, дата, строк, сумма, кнопка «Откатить импорт».

**Источники закупки** — небольшой справочник (TubeCrown, TubeTraffic/ixxx, …): слаг, название, валюта всегда USD.

<a id="networks"></a>
## `/settings/networks`

Справочник сеток: Слаг · Название · Тип (MEDIATED / DIRECT / MARKETPLACE) · Цвет · Показывать в легенде.

- Новая сетка из AdSpyglass создаётся ингестом автоматически, с серым цветом «Прочее». Здесь ей назначают цвет.
- Больше шести цветных сеток нельзя: остальные схлопываются в «Прочее» на всех графиках.
- `own_deals` — системная сетка, её нельзя удалить, цвет — зелёный.

<a id="integrations"></a>
## `/settings/geo` — Гео и тиры

Страны с тиром 1–5 ([ADR 0017](../adr/0017-tiers.md)): таблица «Код · Страна · Тир (селект) · Page loads и выручка за 30 дней», поиск, переключатель «только с трафиком». Массовая вставка «T2: IT, ES; T3: BR, MX» с необязательной причиной. Каждое изменение — строка `AuditLog` (entity `Country`, field `tier`); такие страны сид и миграции больше не перезаписывают. Внизу — последние 20 правок. Служебные коды XX/ZZ (тир 0) не показываются и не редактируются. Тиры читают фикс-дилы (T1–T5), фильтр и сводка «По тирам» на `/geo`, чип тира у гипотез по гео.

## `/settings/integrations`

**Подключения:** AdSpyglass (email + токен) и S3 для сырья — из `.env` на сервере, страница показывает только статус («задан / не задан», последние 4 символа) и кнопку «Проверить соединение». Яндекс Метрика — строка статуса («подключена по OAuth · токен до <дата>», «токен из .env», «не подключена») и ссылка «Настроить» на блок ниже.

**Яндекс Метрика** ([ADR 0018](../adr/0018-metrika-oauth-ui.md)) — подключается из интерфейса, без правки `.env`:

1. **Приложение.** Поля «ID приложения» и «Секрет приложения» из oauth.yandex.ru (у приложения должен быть доступ «Яндекс Метрика: получение статистики, чтение параметров своих и доверенных счётчиков», Redirect URI — «подставить URL для разработки», то есть `https://oauth.yandex.ru/verification_code`). Секрет хранится в базе зашифрованным ключом сервера `APP_SECRET` и в интерфейсе больше не показывается; ID виден хвостом.
2. **Код.** Ссылка «Получить код в Яндексе» открывает страницу согласия под аккаунтом, где лежат счётчики; Яндекс показывает код подтверждения — его вставляют в поле «Код подтверждения» и нажимают «Подключить». Сервер меняет код на OAuth-токен (и refresh-токен), запоминает срок действия и сразу читает счётчики.
3. **Счётчики.** Таблица «Сайт · Сейчас · Счётчик в Метрике · Решение»: по каждому **нашему** сайту (не архивному) ищется активный счётчик, чей сайт или зеркало совпадает с доменом (`www.`, схема и регистр не важны). Решения: **привязать** (один счётчик, у сайта пусто), **уже привязан**, **другой счётчик у сайта** (конфликт — не трогаем), **несколько счётчиков — выбрать руками**, **счётчика нет**. Счётчики без нашего сайта в систему не попадают. «Применить N» записывает только строки «привязать» (с записью в `AuditLog`) и ставит джоб `metrika` за последние 30 дней. «Подтянуть счётчики» повторяет сверку в любой момент.
4. **Обслуживание.** Токен обновляется сам по refresh-токену за 30 дней до истечения (в почасовом джобе `metrika`); «Отключить» забывает токен и приложение (счётчики у сайтов остаются); «Сменить приложение» — другое приложение сбрасывает токены. Если сменился `APP_SECRET`, блок говорит об этом и просит подключить заново; токен из `.env` (`METRIKA_TOKEN`) остаётся запасным путём.

**Разрезы ADOK** ([ADR 0016](../adr/0016-asg-request-plan.md)) — план запросов к AdSpyglass на сутки: галочки по разрезам на сайт (Страны — обязательны; Сетки, Устройства, Источники трафика, Форматы, Зоны по сайту, Часы, Платформы, Браузеры — последние выключены по умолчанию), «прошлых дней в ночь» (1–3), «почасовые итоги — только сегодня». «Зоны по сайту» заменяет один общий запрос зон на запрос по каждому сайту (зоны привязываются фильтром, а не доменом в названии); если ADOK вернёт весь аккаунт, день берётся общим запросом. Справа живой расчёт: ночь = дни × (1 или 2 + разрезы × сайтов), почасовые (24 или 48), запас 30, итог против бюджета `ASG_DAILY_BUDGET` и остаток бэкфиллу; план, не влезающий в бюджет, подсвечен. «Сохранить план» применяется со следующего прогона; бэкфилл и ручной `asg:sites` считают запросы по нему же.

**Ингест:**
- Карточка на каждый джоб: расписание, последний запуск, статус, длительность, строк записано, следующий запуск.
- Лог `IngestRun` за 7 дней: источник · окно · статус · строк · длительность · ошибка (раскрывается) · ссылка на сырой ответ в S3.
- **Ручной перезапуск:** источник, диапазон дат, (опционально) сайт → ставит джоб в очередь и показывает его прогресс.
- **Бэкфилл AdSpyglass** — отдельный блок: «Что грузить» (все разрезы — по плану «Разрезы ADOK»: 2 + разрезы × сайтов запросов на день, окно по умолчанию с 1-го числа текущего месяца; только итоги по сайтам — 1 запрос на день, окно с 1-го числа прошлого месяца) · «С» · «По» (T-3) · сайт. Джоба `asg:backfill` раз в 30 минут грузит дни от новых к старым, сколько влезает в дневной бюджет за вычетом резерва ночного прогона, и сама продолжает на следующие сутки; блок показывает «готово X из Y дней · осталось ≈ N сут.» и кнопку «Отменить». Для ручного `asg:sites` на длинное окно форма считает запросы по плану (сайт × день × разрезы + 2) и требует галочку.

**Лимиты AdSpyglass:** запросов сегодня / дневной бюджет, интервал, состояние паузы и кнопка «Снять паузу» (пауза ставится автоматически после отказа в авторизации, 429 или обрыва соединения).

**Демо-данные:** «Загрузить» — только в пустую базу; «Удалить» — только если в базе демо. Сверху на всех страницах висит плашка «Демо-данные».

**Нераспознанные гео** (`#geo`): доля строк в `XX` за 7 дней (цель — меньше 1%, выше — подсвечивается); сырое название · источник · сколько строк ушло в `XX` · поле выбора ISO-кода с автодополнением. После сопоставления кнопка «Пересчитать» перезаписывает затронутые строки из сырья в S3, без повторного обхода API.

<a id="access"></a>
## `/settings/access`

- Смена пароля приложения: текущий + новый; все сессии, кроме текущей, сбрасываются.
- MCP-токен: показать один раз при создании, перевыпустить, дата последнего использования. URL для коннектора Claude: `https://<домен>/api/mcp`.
