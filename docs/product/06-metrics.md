# 06. Метрики

Все формулы считаются **из сумм**, а не как среднее средних: `SUM(revenue) / SUM(page_loads) × 1000`, а не `AVG(rev_per_k)`. Деление на ноль даёт `NULL`, в UI — `—`. Реализация — единственный модуль `src/lib/metrics.ts` плюс SQL-вьюхи; оба покрыты тестами на одинаковых фикстурах.

## Грануляция источников

| Источник | Минимальный разрез | Что даёт |
| --- | --- | --- |
| AdSpyglass, гео | дата × сайт × сетка × страна × девайс | page loads, показы свои и сетки, клики, выручка. Включает own deals |
| AdSpyglass, зоны | дата × сайт × зона × формат | то же + видимые показы. Own deals не входят |
| Метрика | дата × сайт × страна × девайс | уники, просмотры, визиты, отказы, глубина |
| Закупка | дата × сайт × страна × источник | купленные уники, ставка, расход |
| Фикс-дилы | дата × дил × сайт × страна | загрузки, свои показы, показы рекламодателя, выручка, статус |

Общий знаменатель всех источников — **дата × сайт × страна**. ROMI существует только на нём и выше.

## Базовые метрики

| Метрика | Формула | Формат | Где применяется |
| --- | --- | --- | --- |
| Выручка | `revenue_mediated + revenue_direct` | money | Везде |
| Расход | `SUM(cost)` | money | Сайт × гео и выше. По странам — оценка из `v_site_geo_alloc_daily` ([ADR 0015](../adr/0015-geo-cost-allocation.md)): расход без страны (`ZZ`) за день и сайт разложен по странам дня — ставочный (`cost_rate`: за уника / 1000 загрузок / клик, импорт) пропорционально загрузкам, revshare (`cost_revshare`: доля выручки источника из ADOK) пропорционально выручке страны; день без разреза по странам остаётся «Без страны». Та же вьюха — у алерта «Убыточное гео» и матрицы `/geo`. Раньше было: разложен по загрузкам ([ADR 0008](../adr/0008-forecast-and-geo-cost-allocation.md)) |
| Маржа | `revenue − cost` | money, цвет | Сайт × гео и выше — **до** операционных расходов (KPI сводки, таблицы сайтов, бандлов, гео, вьюхи, MCP `margin`). **После** них (`revenue − cost − opex`, [ADR 0007](../adr/0007-opex-and-calendar-months.md)) — на `/finance`, в P&L-графике сводки, на `/forecast` и в MCP `margin_after_opex`; там это подписано |
| Опер. расходы | `SUM(v_opex_daily.amount)` — цифра месяца / дней в месяце, по дням | money | `/finance`: KPI, таблица по месяцам, P&L (расход сети — по сайтам пропорционально выручке) |
| **ROMI** | `(revenue − cost) / cost × 100%` | percent, цвет | Главная цифра бандла и сайта. Всегда на расход на трафик, без опер. расходов |
| Уники | `SUM(uniques)` — сумма дневных | int | Подпись в UI: «сумма дневных уников» |
| RPM на уника | `revenue / uniques × 1000`, где в числителе только выручка сайто-дней, у которых Метрика посчитала уников (сайт без Метрики не завышает RPM сети и бандла) | money | Сравнение сайтов и бандлов |
| **Rev / 1000 loads** | `revenue / page_loads × 1000` | cpm | Основная метрика сравнения сеток внутри гео |
| CPM | `revenue / imps_own × 1000` | cpm | Только внутри одного формата |
| Viewable CPM | `revenue / views × 1000` | cpm | BANNER, NATIVE |
| View rate | `views / imps_own` | percent | BANNER, NATIVE. < 15% — проблема вёрстки |
| Fill rate | `imps_own / page_loads` | percent | Сколько запросов закрылось |
| Дискрепанси | `(imps_own − imps_network) / imps_own` | percent | Отрицательная — рекламодатель насчитал больше |
| Множитель дила | `imps_reported / imps_own` | ×1.00 | Фикс-дилы, > 1.5× — предупреждение |
| Cost / unique | `cost / uniques_bought` | cpm (4 знака) | Цена входа |
| Глубина | `pageviews / uniques` | 0.00 | Множитель между ценой уника и показами |
| Доля в выручке | `revenue / SUM(revenue) по разрезу` | share | Зоны, форматы, сетки — вместо ROMI |
| Доля объёма | `page_loads / SUM(page_loads) по site × country` | share | Сетки |
| Ранг по цене | `RANK() по rev_per_1k_loads DESC внутри site × country` | int | Сетки |
| Эффективный CPM дила | `revenue_confirmed / imps_own × 1000` | cpm | Карточка дила |
| Подтверждённая доля | `revenue_confirmed / revenue` | percent | `/finance` |

**rCPM в интерфейс не выводим.** Он считается на свои показы и завышает источники с низким филом. Для сравнения источников — только rev / 1000 loads.

**ROMI в разрезах без расхода** (зоны, форматы, сетки) не определён: на его месте стоит доля в выручке.

## Дельты

- Сравнение с предыдущим равным периодом: 7 дней против предыдущих 7.
- Для денежных и счётных метрик — дельта в процентах.
- Для процентных (ROMI, fill rate, view rate) — дельта в **процентных пунктах**.
- Если база сравнения равна нулю, дельта не показывается.

## Пороги подсветки

| Где | Правило |
| --- | --- |
| Заливка ROMI и маржи в таблицах | Только при отклонении > 20% от среднего по разрезу; ниже нуля — всегда красная |
| Дискрепанси | до ±10% нейтрально · ±10–25% `--warning` · дальше `--negative` |
| View rate | < 15% — бейдж «не видна» |
| Доля зоны | < 1% выручки — бейдж «кандидат на снос» |
| Множитель дила | > 1.5× — `--warning` |
| Свежесть ингеста | > 2 ч — жёлтая точка, failed — красная |

<a id="alerts"></a>
## Алерты

Считаются SQL-правилами ночью (`derive`, 04:45 UTC) и при старте воркера, складываются в таблицу `Alert`. Ключ алерта — `rule + entity`; повторное срабатывание обновляет существующий, а не создаёт новый. Каждое правило отдаёт **действие** отдельным полем (`payload.action`) — его показывают «Рекомендации»; сообщение — только «почему». Все правила пропускают архивные сайты; правила по данным (1–6) смотрят только дни до сегодняшнего, а если за вчера нет разреза по странам, их алерты не закрываются (нет данных ≠ всё хорошо).

| # | Правило | Условие | Уровень | Рекомендуемое действие |
| --- | --- | --- | --- | --- |
| 1 | Убыточное гео | site × country за 7 дней: revenue < cost, cost > $5, ≥ 10 000 загрузок; только дни, когда у сайта есть разрез по странам; расход `ZZ` (источники) разложен по странам дня по загрузкам, как в таблице гео; `XX` не учитывается | critical | Снизить закупку гео или поднять флор |
| 2 | Инверсия waterfall | site × country за 7 дней: сетка с рангом по цене > 3 держит > 30% объёма, loads > 10 000. Ранг — только среди сеток с ≥ 5% загрузок; системные сетки (own deals, «все сетки») не участвуют. «Под риском» = (rev/1000 loads лучшей сетки − этой) × её loads / 1000 за 7 дней | warning | Переставить сетку ниже, объём отдать сетке X |
| 3 | Аномальная дискрепанси | сетка × гео: \|дискрепанси\| > 25% два дня подряд при > 5 000 показов; системные сетки не участвуют. Отрицательная и множитель > 2× → critical. «Под риском» = спорные показы (\|наши − сетки\|) × CPM сетки / 1000 за 2 дня — оценка, помечена `payload.estimate` | warning / critical | Сверить счётчики; перевести дил на оплату за загрузку |
| 4 | Невидимая зона | BANNER/NATIVE, view rate < 15% при > 50 000 показов за 7 дней; нужны реальные просмотры (без `banner_view_rate` от ADOK просмотров нет — правило молчит) и выручка > 0; «под риском» = выручка при view rate 35% (viewable CPM × показы × 0,35) − факт, не меньше $5; зоны, место которых занято дилом, не учитываются | warning | Поднять зону выше фолда или перенести на другое место |
| 5 | Мёртвая зона | за 30 дней < 1% выручки зон **того же формата** на сайте при > 5% их показов (CPM сравним только внутри формата); ≥ 50 000 показов, данные за последние 3 дня, зона активна, место не занято дилом; «под риском» = выручка по CPM формата − факт | warning | Снести, отдать место формату с высоким CPM |
| 6 | Низкий фил формата | fill rate < 25% при > 100 000 запросов за 7 дней. «Под риском» = незаполненные запросы × ¼ CPM формата / 1000 — консервативная оценка бэкфилла, помечена `payload.estimate` | warning | Подключить бэкфилл |
| 7 | Дил без цифр | период биллинга закрыт больше 7 дней назад, данных рекламодателя нет | warning | Запросить отчёт у рекламодателя |
| 8 | Просроченная оплата | выставлено, срок оплаты прошёл, остаток к оплате > 0 | warning (> 30 дней — critical) | Напомнить рекламодателю |
| 9 | Ингест упал | последний `IngestRun` источника failed или старше 3 часов | critical | Открыть `/settings/integrations` |
| 10 | Фикс-дил заканчивается | активный или приостановленный дил с датой конца: осталось ≤ 7 дней; дата прошла, а дил всё ещё активен | warning при 4–7 днях; critical при ≤ 3 днях и после даты конца | Договориться о продлении (новая дата конца) или завершить дил и освободить место |

| 11 | Источник без подтверждённой доли | источник трафика, созданный из ADOK с долей расхода по умолчанию (100%), принёс сумму за 7 дней, а владелец долю не задавал (`CostSource.confirmed = false`) | warning | Задать долю расхода в Настройки → Расход (0% — бесплатный трафик) |

Правила 7–11 добавлены к спецификации для раздела фикс-дилов, надёжности ингеста и расхода по источникам.

**«Принято к сведению».** Алерт с суммой под риском скрывается на 30 дней и возвращается раньше, если сумма выросла больше чем вдвое. Алерт без суммы (ингест, дил без цифр) скрывается на 7 дней — у него нет числа, которое могло бы его разбудить (`SNOOZE_DAYS` в `rules.ts`). Правила 7 и 9 денег не оценивают: у «дила без цифр» их ещё нет, а «ингест упал» на `/alerts` идёт первым внутри своего уровня — без него не считается ничего остального.

**Этапы правила 10.** В `payload.stage` записывается порог: 7, 3, 1 или 0 (дата прошла). Смена этапа — новое уведомление: `firstSeenAt` сбрасывается на сегодня, снятое «принято к сведению» возвращается. Так один дил поднимается в алертах три раза — за неделю, за три дня и за день, — а не висит одной строкой. Деньги под риском — выручка дила за последние 30 дней. Дилы без даты конца правило не трогает.

<a id="forecast"></a>
## Прогноз месяца

`темп = Σ(метрика за последние N полных дней) / N`, где полный день — день до сегодняшнего с выручкой AdSpyglass **и** разрезом по источникам трафика (без него расход дня = 0 не потому, что трафик бесплатный, а потому что не загружен; такой день пропускается, а не считается нулём); N = 3, 7 или 14 (по умолчанию 7), полных дней меньше N — берутся те, что есть. `прогноз месяца = факт с начала месяца + темп × дней впереди` (сегодняшний день — впереди). Темп считается отдельно для выручки и расхода на трафик; операционные расходы известны на каждый день месяца из `OpexEntry`; маржа прогноза = выручка − расход − опер. расходы; ROMI — на расход на трафик. Без сезонности по дням недели и без тренда — сознательно: при 27 сайтах и трёх днях данных любая модель сложнее среднего даёт ложную точность ([ADR 0008](../adr/0008-forecast-and-geo-cost-allocation.md)). Реализация — `src/lib/forecast.ts` (`projectMonth`), тесты на синтетике.

## Гипотезы

Собираются ночью (`derive`, после алертов) и при старте воркера из двух источников и хранятся в `Hypothesis` ([ADR 0013](../adr/0013-hypotheses.md)). Из **алертов** — действие правила (`payload.action`) становится первым предложением гипотезы, сообщение — пояснением; ключ правило + объект общий с алертом, поэтому алерт и правило про один объект — одна гипотеза. Эффект алерта приводится к месяцу по окну правила (`ALERT_WINDOW_DAYS`: убыточное гео, инверсия, невидимая зона, фил и доля источника — 7 дней; дискрепанси — 2; мёртвая зона и конец дила — 30): $12 под риском за неделю → $51.43/мес. Просроченная оплата — долг, показывается как есть с подписью «долг» (`evidence.debt`); дил без цифр и ингест эффекта не имеют. Из **правил по дневной аналитике** (`src/server/domain/hypotheses.ts`, окна 7 и 30 дней, итоги по сайтам, медианы — по сайтам с трафиком; «в месяц» = окно × 30 / дней):

| Ключ | Разрез | Условие | Гипотеза | Эффект $/мес | Метрика |
| --- | --- | --- | --- | --- | --- |
| `site_loss` | сайт | за 7 дней расход на трафик > выручки (расход > 0) | снизить закупку или поднять флор; проверить убыточные гео | −маржа | маржа |
| `margin_drop` | сайт | маржа упала ≥ 20% к прошлой неделе при выручке прошлой недели > $50 и марже > 0; в тексте — разрез (гео / сетка / формат), просевший сильнее всего | вернуть то, что сломалось | падение | маржа |
| `site_below_bundle` | сайт × бандл | rev/1000 loads сайта < 75% медианы бандла (≥ 3 сайта с ≥ 50 000 loads) | выровнять сетки, флоры и форматы с лидером бандла | (медиана − своё) × loads / 1000 | rev/1k |
| `geo_below_network` | сайт × гео | rev/1000 loads страны < 70% медианы той же страны по сети (≥ 3 сайта с ≥ 10 000 loads из неё; не ZZ/XX) | поднять флор или сменить сетку для гео | (медиана − своё) × loads / 1000 | rev/1k |
| `format_missing` | сайт × формат | формат зарабатывает на ≥ 50% сайтов бандла (≥ 2) и отсутствует на сайте (≥ 3 сайта с ≥ 20 000 loads) | добавить формат (зона или фикс-дил на место) | медианный rev/1k формата у пиров × loads сайта / 1000 | выручка формата |
| `network_underused` | сайт × сетка | сетка в топ-2 по медианному rev/1k на пирах бандла (≥ 2 сайта с объёмом), на сайте < 10% объёма, её медиана выше среднего rev/1k сайта | поднять сетку в waterfall до 10% объёма | (медиана сетки − rev/1k сайта) × 10% loads / 1000 | rev/1k |
| `network_below_floor` | сайт × сетка | ниже флора сайта (флор > 0) и ≥ 10% объёма за 7 дней | поднять флор до X или опустить в waterfall | (флор − rev/1k) × loads / 1000 | rev/1k |
| `source_eats_revenue` | сайт × источник | расход источника ≥ 60% выручки сайта и > $5 за 7 дней | снизить закупку или договориться о доле | расход − 50% выручки | доля расхода |
| `source_above_revenue` | сайт × источник | цена 1000 loads источника > выручка сайта на 1000 loads (≥ 10 000 loads) — уровень не ниже CRITICAL | срезать или переторговать источник | (цена − выручка на 1000) × loads / 1000 | цена 1000 loads |
| `bundle_cost_share` | бандл | доля расхода в выручке бандла ≥ доля сети + 10 п.п. при выручке > $100 | привести закупку бандла к доле сети | (доля − доля сети) × выручка | доля расхода |
| `deal_below_rotation` | дил × сайт | rev/1000 loads активного дила < 70% ротации того же формата на сайте (≥ 10 000 loads дила) | поднять цену дила или вернуть место в ротацию | (ротация − дил) × loads / 1000 | rev/1k |
| `dead_zone` | зона | за 30 дней < 1% выручки зон того же формата на сайте при > 5% их показов, ≥ 50 000 показов | снести или отдать место формату с более высоким CPM | — | выручка зоны |
| `invisible_zone` | зона | BANNER/NATIVE, view rate < 15% при > 50 000 показов за 7 дней, просмотры и выручка > 0 | поднять выше фолда или сменить место | выручка при 35% view rate − текущая | view rate |
| `free_places` | сайт | свободные места на сайте из топ-10 по выручке (выручка > 0) | продать фикс-дил или включить ротацию | свободных мест × медианная выручка занятого места сайта за 7 дней (ячейки `/inventory` с выручкой > 0); нет занятых мест с выручкой — 0 | выручка |

Уровень: эффект ≥ $300/мес — CRITICAL, ≥ $30 — WARNING, иначе INFO (у `site_loss` и `source_above_revenue` не ниже CRITICAL). Пороги правил по зонам равны порогам алертов №4 и №5 — между ночными прогонами правило лишь дублирует алерт. Сортировка: critical → warning → info, внутри — по эффекту.

**Доказательства.** Каждое правило сохраняет цифры, на которых стоит, в `evidence`; карточка показывает их одной строкой (`evidenceLine` в `src/server/domain/hypotheses.ts`): «у вас $0.50 · медиана бандла $1.20 · лидер domain $2.00 · 4 сайта за 7 дн.», для `margin_drop` — топ-3 просевших разрезов. У гипотез из алертов цифры уже в тексте — строки нет.

**Измерение.** «Принять» фиксирует `baseline` — метрику гипотезы за 14 дней до дня принятия; «Завершить» — `result` за последние 14 дней, но не раньше дня принятия. Меньше 7 дней данных — значение не пишется («мало данных»). Метрика считается по объекту гипотезы: зона → `v_zone_daily`; сайт × сетка → `v_network_geo`; сайт × формат → `v_format_daily`; сайт × источник → `FactCost` / `FactTrafficSource` (цена 1000 loads, доля расхода — к выручке сайта); дил → `v_deal_daily`; иначе срез сайта / бандла / страны `v_site_geo_daily` (выручка, маржа, rev/1k, RPM, доля расхода). Дельта в UI — `(result − baseline) / |baseline|`; для цены и доли расхода меньше — лучше.

## Рекомендация флора

Колонка в таблице сеток, не алерт. Считается **по сайту за выбранный период** (ADOK не отдаёт сетку × страну, а формат есть только у зон), а не по `site × country × format` за 14 дней, как в спецификации:

```
floor = rev_per_1k_loads лучшего источника × 0.4 + второго × 0.6
        (60-я точка между двумя лучшими источниками сайта за период)
```

Кандидаты во «флор» — только медиационные сетки с ≥ 5% загрузок: own deals (прямые), строка «AdSpyglass (все сетки)» (дни без разреза по сеткам) и сетка с горсткой загрузок флор не задают и бейдж «ниже флора» не получают.

Источник с rev / 1000 loads ниже флора получает бейдж «ниже флора»: он занимает слот в waterfall, не оплачивая его.

- Выручка за день в дашборде сходится с кабинетом AdSpyglass в пределах ±2%.
- Сумма по сайтам бандла = итог бандла.
- Итог сети = сумма по сайтам, а не по бандлам.
- Own deals не задваиваются с медиацией.
- Сумма дневной раскладки фикс-дила = сумма периода до цента.
- Нераспознанных гео меньше 1% строк.
