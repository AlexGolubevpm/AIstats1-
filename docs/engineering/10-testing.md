# 10. Тестирование

## Правило

**Любое изменение поведения приходит вместе с тестами.** PR без тестов на новую или изменённую логику не мержится. Исключения — только правки документации, текстов и стилей без логики; в описании PR это указывается явно.

Баг чинится в два шага: сначала тест, который воспроизводит баг и падает, затем исправление.

## Инструменты

| Уровень | Инструмент | Что тестируем |
| --- | --- | --- |
| Unit | Vitest | `lib/metrics`, `lib/format`, `lib/period`, `server/domain/*`, нормализация, парсеры ответов API |
| Интеграционные | Vitest + Postgres (сервис в CI; локально `TEST_DATABASE_URL`) — на каждый прогон создаётся база `tubestat_test_<pid>` и применяются миграции | Миграции, вьюхи, upsert ингеста, SQL алертов, server actions, права роли `mcp_reader`, инструменты MCP |
| Компоненты | Vitest + Testing Library | `DataTable` (форматирование по `kind`, сортировка, итоги), `KpiCard`, формы дилов (валидация, авторасчёт) |
| E2E | Playwright (Chromium) | Ключевые сценарии в браузере против собранного приложения и тестовой базы |
| Скрипты деплоя | bash-тесты в `tests/ci/*.test.sh` | Нормализация ключа, валидность compose, синтаксис скриптов |

## Что обязано быть покрыто

- **Каждая формула** из [каталога метрик](../product/06-metrics.md): нормальный случай, деление на ноль, сумма против среднего средних.
- **Ингест:** маппинг реального ответа API (фикстуры из `docs/asg-samples/` и `tests/fixtures/metrika/`) → строки фактов; повторный прогон не создаёт дублей; рестейт перезаписывает; неизвестная страна → `XX`; неизвестная сетка создаётся.
- **Вьюхи:** на фикстурной базе с двумя бандлами, общим сайтом, own deals и расходом:
  - сумма по сайтам бандла = итог бандла;
  - итог сети ≠ сумма бандлов при пересечении;
  - own deals не задваиваются.
- **Расход:** выбор ставки от частного к общему; импорт перекрывает расчёт; откат импорта возвращает расчёт.
- **Фикс-дилы:** авторасчёт суммы для каждой модели оплаты; раскладка периода по дням сходится до цента; приоритет подтверждено > выставлено > прогноз; запрет пересечения периодов; исправление создаёт версию.
- **Алерты:** каждое правило срабатывает на своей фикстуре и не срабатывает на соседней; повторное срабатывание обновляет алерт; «принято к сведению» скрывает на 30 дней.
- **MCP:** `query` отклоняет не-SELECT, несколько операторов и таблицы; навязывает `LIMIT`; роль не читает таблицы.
- **Доступ:** все страницы и API, кроме `/login`, `/api/health`, `/api/mcp`, отдают 401/redirect без сессии.

## E2E-сценарии (минимум)

1. Вход по паролю → сводка открывается, KPI не пустые.
2. Сводка → бандл → сайт → вкладка «Гео» → раскрыть страну; URL сохраняет состояние, «назад» возвращает срез.
3. Добавить сайт в настройках → «Проверить» (API замокан) → сайт виден в `/sites`.
4. Завести дил → внести данные за период → подтвердить оплату → сумма на `/finance` в статусе «Подтверждено».
5. Импорт CSV расхода → предпросмотр → запись → ROMI на странице сайта изменился.

## Фикстуры

- Реальные ответы API после спайка кладутся в `tests/fixtures/` с обезличенными доменами. Токены и email не попадают в фикстуры никогда.
- Фабрики тестовых данных — `tests/factories/*.ts`, по одной на модель.
- Единая «эталонная сеть» `tests/factories/network.ts`: 2 бандла, 3 сайта (один в двух бандлах), 2 страны, сетка + own deals, дил `DIRECT` и дил `VIA_ASG`, 2 дня. На ней проверяются вьюхи, алерты, сервисы и MCP.

## Покрытие

- Цель: **80% строк** по `src/lib` и `src/server` (`npm run coverage`). В `check` порог пока не включён.
- Покрытие — индикатор, а не цель: тест без проверки результата не считается тестом.

## Команды

```bash
npm test               # unit + компоненты
npm run test:int       # интеграционные (нужен Postgres: TEST_DATABASE_URL)
npm run test:all       # unit + интеграционные + bash-тесты
```

В CI job `check` запускает lint, typecheck, `test`, `test:int`, `test:e2e`, bash-тесты и сборку образа. Merge в `main` возможен только при зелёном `check`.
